# Python: KI is a library call
import openai

def summarize(text):
    r = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role":"user","content":text}]
    )
    return r.choices[0].message.content

def translate(text, lang):
    r = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role":"system",
          "content":f"Translate to {lang}"},
          {"role":"user","content":text}]
    )
    return r.choices[0].message.content

text = read_file("news.txt")
summary = summarize(text)
german = translate(summary, "de")
print(german)

The Semantic Pipeline Runtime

Die Semantic Pipeline Runtime

Pipe is not another scripting language. It's a runtime where semantics and computation share the same abstraction level.

Pipe ist keine weitere Skriptsprache. Es ist eine Runtime in der Semantik und Berechnung auf derselben Abstraktionsebene leben.

🔗

Pipeline-Native

Pipeline-Nativ

Data flows top to bottom through transformation stages. Every stage receives output from the previous — no nesting, no boilerplate.

Daten fließen von oben nach unten durch Transformationsstufen. Jede Stufe erhält die Ausgabe der vorherigen — keine Verschachtelung, kein Boilerplate.

Why Pipe is different

Warum Pipe anders ist

Not incremental improvement. A category shift.

Keine inkrementelle Verbesserung. Ein Kategorie-Sprung.

01

AI operations are language primitives — not library calls

KI-Operationen sind Sprachbestandteile — keine Library-Aufrufe

In Python you import openai and call chat.completions.create(). In Pipe you write > summarize. The language doesn't distinguish between an AI call and a sort operation — and that's the point.

In Python importierst du openai und rufst chat.completions.create() auf. In Pipe schreibst du > summarize. Die Sprache unterscheidet nicht zwischen einem KI-Call und einer Sortier-Operation — und genau darum geht es.

02

Parallel AI with native concurrency

Parallele KI mit nativer Nebenläufigkeit

ai_batch processes hundreds of texts in parallel using Go goroutines. Rate limiting built-in. No async/await, no Promise.all — just data flowing.

ai_batch verarbeitet hunderte Texte parallel mit Go-Goroutines. Rate-Limiting eingebaut. Kein async/await, kein Promise.all — nur fließende Daten.

03

Streaming responses in real time

Streaming-Antworten in Echtzeit

ai_stream delivers tokens as they arrive — like watching ChatGPT think. Live output, full text returned for pipeline continuation.

ai_stream liefert Tokens sobald sie ankommen — als würdest du ChatGPT beim Denken zusehen. Live-Ausgabe, vollständiger Text für Pipeline-Weiterverarbeitung.

04

LLM-controlled tool execution

LLM-gesteuerte Tool-Ausführung

Define a Pipe function. Register it with ai_tool. The model autonomously decides when to invoke it, passes arguments, receives results, and continues.

Definiere eine Pipe-Funktion. Registriere sie mit ai_tool. Das Modell entscheidet autonom, wann es sie aufruft, übergibt Argumente, erhält Ergebnisse und macht weiter.

05

RAG-ready with native embeddings

RAG-bereit mit nativen Embeddings

embed converts text to vectors. nearest finds semantically similar documents. cosine_sim compares meaning. Build retrieval-augmented generation in 10 lines.

embed wandelt Text in Vektoren um. nearest findet semantisch ähnliche Dokumente. cosine_sim vergleicht Bedeutung. Baue Retrieval-Augmented Generation in 10 Zeilen.
