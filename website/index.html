Python → Pipe comparison
# Python: KI is a library call
import openai

def summarize(text):
    r = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role":"user","content":text}]
    )
    return r.choices[0].message.content

def translate(text, lang):
    r = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role":"system",
          "content":f"Translate to {lang}"},
          {"role":"user","content":text}]
    )
    return r.choices[0].message.content

text = read_file("news.txt")
summary = summarize(text)
german = translate(summary, "de")
print(german)
→
-- Pipe: KI is part of the data flow
read_file "news.txt"
    > summarize       -- LLM call
    > translate "de"  -- LLM call
    > print           -- output

The Semantic Pipeline Runtime

Pipe is not another scripting language. It's a runtime where semantics and computation share the same abstraction level.

🔗

Pipeline-Native

Data flows top to bottom through transformation stages. Every stage receives output from the previous — no nesting, no boilerplate.

🧠

AI as Primitive

25 built-in AI operations: summarize, translate, classify, extract, ask, ai_stream, ai_batch, ai_with_tools, embed, and more.

📦

Single Binary

One ~10 MB statically linked binary. No venv, no pip, no npm, no Docker. Compile once, deploy anywhere.

⚡

Bytecode VM

Tree-walker for development, bytecode VM for production — same code, ~7× faster. Automatic bytecode caching.

🔌

Multi-Provider

OpenAI, Anthropic (Claude), DeepSeek. Switch with one line: ai_provider "deepseek". One API, any backend.

🛠️

Tool Calling

Register Pipe functions as LLM tools. The model decides when to call them — your code executes, the model responds.

Why Pipe is different

Not incremental improvement. A category shift.

01

AI operations are language primitives — not library calls

In Python you import openai and call chat.completions.create(). In Pipe you write > summarize. The language doesn't know the difference between an AI call and a sort operation — and that's the point.

02

Parallel AI with native concurrency

ai_batch processes hundreds of texts in parallel using Go goroutines under the hood. Rate limiting built-in. No async/await, no Promise.all — just data flowing.

03

Streaming responses in real time

ai_stream delivers tokens as they arrive — like watching ChatGPT think. Live output, full text returned for pipeline continuation.

04

LLM-controlled tool execution

Define a Pipe function. Register it with ai_tool. The model autonomously decides when to invoke it, passes arguments, receives results, and continues the conversation. Multi-round agentic loop built in.

05

RAG-ready with native embeddings

embed converts text to vectors. nearest finds semantically similar documents. cosine_sim compares meaning. Build retrieval-augmented generation pipelines in 10 lines.

Multi-Step RAG Pipeline

docs: read_lines "knowledge.txt"
vectors: embed_batch docs
q: embed "How does the VM work?"
top: nearest q vectors 3
context: join top "\n---\n"
ask ("Context: " ++ context)
    > print

Parallel Batch Processing

texts: read_lines "articles.txt"
ai_rate_limit 10
ai_batch "Summarize in one sentence." texts
    > sort
    > join "\n"
    > save "digest.txt"

Get Started

Three commands to your first AI pipeline.

# 1. Clone and build
git clone https://github.com/harry/pipe && cd pipe && make build

# 2. Set your API key (OpenAI, Anthropic, or DeepSeek)
export DEEPSEEK_API_KEY="sk-..."

# 3. Run your first pipeline
./bin/pipe -c 'ai_provider "deepseek"
ask "What makes Pipe different from other languages?" > print'

Run with Bytecode VM

~7× faster execution for production.

./bin/pipe -vm -q script.pipe

Self-Extracting Binary

Ship your pipeline as a standalone executable.

./bin/pipe -build script.pipe -o mytool
./mytool
